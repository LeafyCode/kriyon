# Kriyon v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a loosely-coupled Tauri v2 desktop GUI that hosts the user's own authenticated `claude` CLI in a real terminal, with a reconstructed structured view, multi-session/worktree management, sidebar status, notifications, and clean copy.

**Architecture:** Rust core (PTY host via `portable-pty`, JSONL transcript watcher, status engine, git/worktree, SQLite) + React/TS frontend in WKWebView (xterm.js + WebGL terminal, structured "Studio" view, sidebar, inspector, palette). PTY bytes stream over a binary `tauri::ipc::Channel`; structured/status updates are JSON events. The terminal is the source of truth; the structured view is a best-effort reconstruction from `~/.claude/projects/<hash>/<id>.jsonl`. Subscription auth = interactive PTY only (ToS-safe); an API-key engine is designed-for (a `SessionEngine` trait) but not built in v1.

**Tech Stack:** Tauri v2 (`@tauri-apps/cli` 2.11.x, `tauri` 2.10.x, Rust 1.88 toolchain), React + TypeScript + Vite, pnpm, `@xterm/xterm` 6 + addon-webgl, `portable-pty` 0.9, `notify` 8, `rusqlite`, Biome + Ultracite, Lefthook + commitlint, Vitest + React Testing Library, `cargo test`.

**Read first:** `docs/superpowers/specs/2026-06-16-kriyon-design.md` (the spec). Work on the **`dev`** branch only. Keep it lean — do not over-engineer.

**Standing rule for the implementer:** Library APIs move fast. Before writing code against Tauri/xterm/portable-pty/notify/Biome/Ultracite/Lefthook, pull current docs via the **context7** MCP (`resolve-library-id` → `query-docs`) and verify signatures. Versions below were correct on 2026-06-16; bump if newer stable exists.
